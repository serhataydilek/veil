# ADR 012: Android local protection key

## Status

Accepted for Android local-state protection. This does not select Veil protocol identity or secure-session cryptography.

## Context

Phase 1B needs a small, Android-only at-rest protection substrate before any future local sensitive state can be stored. The platform key must remain separate from a future Veil cryptographic identity.

## Decision

- Use the platform `AndroidKeyStore` directly, not deprecated AndroidX Security Crypto APIs.
- Generate a non-exportable AES-256 key restricted to `PURPOSE_ENCRYPT` and `PURPOSE_DECRYPT`, GCM block mode, and no padding.
- Use the constant internal versioned alias `veil.local-protection.v1`. It is neither user-derived nor a protocol identifier.
- Store only an encrypted provisioning sentinel in the app-private `noBackupFilesDir` file `veil-local-state.v1`.
- Encrypt with `AES/GCM/NoPadding`, provider-generated randomized IVs, and the fixed non-secret AAD label `veil.local-state.v1`.
- Encode a small versioned envelope with magic, version, IV length, IV, ciphertext length, and ciphertext/authentication tag. Ciphertext is bounded to 4 KiB.
- Keep VLP1 at a fixed 12-byte IV and fail provisioning safely if a provider returns another IV length. Read the physical envelope through a bounded stream before allocation: at most its 4,118-byte maximum plus one byte to identify overflow.
- Persist with `AtomicFile`; a failed write reports failure and does not claim the new state is ready.
- If ciphertext exists but the Keystore key is missing or unavailable, fail closed as `KEY_UNAVAILABLE`. Do not create a replacement key or reset state.
- If state cannot authenticate, parse, or use a supported format, fail closed as `CORRUPT_OR_UNREADABLE`. Do not auto-reset it.
- Purge is explicit. It deletes the logical Keystore alias and state file, then verifies both references are absent before reporting completion. Partial cleanup is reported as incomplete.
- Do not request StrongBox. Normal AndroidKeyStore is used; protection level is internal diagnostic information only.
- Do not bind the key to biometric or device-credential authentication. App-lock policy remains deferred.
- Keep protected-state work outside Compose: application state schedules status, provision, and any future purge operation on an IO dispatcher, then updates UI state on the main dispatcher. Known provider/JCA/I/O failures fail closed.

No Veil identity key, contact ID, session key, signing identity, rendezvous key, or server-visible identifier is generated by this decision.

## Consequences

Future approved identity or session material can later be protected under this boundary, but that work requires separate protocol and storage decisions. Platform behavior still requires Android-version and device validation. Local encryption does not protect an already unlocked or fully compromised endpoint. If the Keystore key is lost, there is no recovery for the protected state.
