# Visual principles

Veil is calm, restrained, modern, and text-first. It must feel like a deliberate private communication tool, never a stripped-down social network or security theatre.

1. **Quiet hierarchy.** One clear primary action per context; restrained surfaces, dividers, and emphasis. No dashboards, badge clusters, ubiquitous cards, decorative gradients, or engagement ornament.
2. **Content first.** Conversation text is the visual object. There are no avatars, profiles, profile imagery, or social identity treatment.
3. **Privacy without theatrics.** Do not scatter lock symbols or “secure/encrypted” labels across normal screens. Explain security only when a user must decide, such as identity verification or destructive action.
4. **Minimal metadata.** Show a local fact only when it helps understand a state, perform an action, or avoid a security mistake. Internal relay, delivery, session, and peer-presence details do not become UI merely because they exist.
5. **Calm failure.** Warnings explain the local condition and safe next step, never claim an attack, account problem, or peer behavior without evidence.
6. **Accessible restraint.** Quiet is not low contrast, tiny touch targets, or color-only meaning. System theme, scalable text, screen readers, and motion reduction are requirements.

Avoid hacker terminals, neon/matrix-green, masks, military branding, cyberpunk, and claims of anonymity, untraceability, or invulnerability.

## Theme direction

Support system theme with equally complete light and dark modes. Use semantic roles—background, surface, elevated surface, primary/secondary/muted text, accent, warning, destructive, success, divider—not fixed implementation colors. Accent guides action, not identity or security truth; green is not the default proof of safety. Meet platform contrast guidance in both themes and preserve the same information hierarchy.

## Typography and density

Use platform/system typography initially. Roles are display, screen title, section title, body, message, secondary, metadata, action, destructive action, and monospace ID. IDs may use grouped monospace for transcription; normal prose and messages do not. Respect dynamic type and readability at every scale.

Use semantic spacing for page margins, vertical rhythm, lists, composer, and dialogs. Rows remain scannable without enterprise-table density; empty space serves grouping rather than spectacle. All interactive targets meet platform accessibility size guidance; dialogs retain clear separation between explanation and actions.
